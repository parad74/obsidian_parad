# Пошаговое создание библиотеки Domain Model — v2

Пользовательская точка входа и основной источник начальных вопросов. Карта ответственности и зависимостей — [[Documents/Architectures/Data Model Harness]].

## Что создаётся

По запросу создаётся библиотека `<Service>.Model` или полный стартовый solution с ExportImport. Состав, перенос готового образца и подключение локального SelectParam определяются [[Commands/Create Project Domain Model by Step#Состав solution]]. Профиль приложения задаётся отдельно; сохранённый пример не подставляет его без выбора.

## Параметры по умолчанию

Перед созданием приложения или нового проекта Машина по одному спрашивает каждый необходимый для запрошенного состава параметр, который ещё не задан Parad, не согласован для текущего применения и не определяется однозначно существующим проектом. Формат вопроса: предлагаемый вариант из первого образца и редактируемое поле для своего значения (свободный ответ). Значения таблицы ниже служат предложениями, а не разрешением применить их без ответа. Уже заданные параметры повторно не спрашиваются. Это правило действует и при добавлении нового проекта в существующий solution.

| Параметр | Предлагаемый вариант или правило определения |
| --- | --- |
| Имя сервиса, если ещё не определено | Вопрос: `Monitor` или своё значение |
| Проект и namespace Domain Model | `<Service>.Model` |
| Target framework Model и SelectParam | `netstandard2.0` |
| Пакет Model для готового образца | `System.ComponentModel.Annotations` `4.7.0` |
| Проект доступа к данным при его запросе | `<Service>.Model.Sqlite.CodeFirst.ExportImport` |
| Namespace EF-проекта | `<Service>.Sqlite.CodeFirst` |
| Target framework EF-проекта | `netcoreapp3.1` |
| Семейство EF и версия | EF Core `3.1.9` |
| СУБД и подход | SQLite, Code First |
| Пакет провайдера | `Microsoft.EntityFrameworkCore.Sqlite` `3.1.9` |
| Логирование EF-проекта | `Microsoft.Extensions.Logging` `3.1.9` |
| Зависимости SelectParam | `EntityFramework` `6.4.0`, `Microsoft.Windows.Compatibility` `3.1.1` |
| Логическое имя БД | Отдельный вопрос при старте ExportImport: `MonitorDb` из образца или своё значение; не выводится автоматически из имени сервиса |
| Контекст | `<ИмяБД>Context`, производное от выбранного логического имени БД; например, `WarehouseDbContext` для `WarehouseDb` |
| Имя файла БД и расположение, если СУБД использует файл | Имя вводится без расширения: `monitor` или своё значение; расположение определяется вопросом из раздела «Строка подключения SQLite» для SQLite. Расширение зависит от выбранной СУБД; для текущего SQLite-профиля — `.db`, итоговый пример `monitor.db`. Для серверной СУБД без файла подключения такой вопрос не задаётся |
| Имя нового отдельного solution | `<Service>.sln` |

Состав файлов берётся из соответствующего готового образца и его архитектурной карточки. Значения сверены с текущими `.csproj` в `Sources/Architectures/LibProject/netstandard2.0/Monitor.Model/`, `Sources/Architectures/LibProject/netstandard2.0/SelectParam/` и `Sources/Architectures/LibProject/netcoreapp3.1/Monitor.Model.Sqlite.CodeFirst.ExportImport/`.

Сначала учитываются явно указанные параметры, фактические solution/проекты и ранее согласованные решения текущей работы. Остальные необходимые параметры выбираются через вопросы: вариант из образца или своё значение. Машина показывает краткую сводку выбранных параметров и проверяет совместимость с целевым solution. При несовместимости показывает конкретный конфликт и уточняет решение до создания зависящего от него проекта. Версии автоматически не подстраиваются под solution и не обновляются без решения Parad. Для другой СУБД или семейства EF выбирается и проверяется соответствующий провайдер; SQLite-пакет не подставляется для другой СУБД.

В режиме интеграции используется указанный существующий solution; имя нового solution к нему не применяется. Расположение берётся из запроса или однозначного рабочего контекста, а при их отсутствии уточняется. Состав solution определяется запросом и необходимыми проектными зависимостями; общего запрета добавлять проекты нет. Defaults не являются командой «сделай всё» и не отменяют отдельных правил migrations. Модель согласуется возвратом проверенного Excel, после чего весь запрошенный комплект создаётся одним проходом.

### Порядок вопросов перед созданием

Вопросы задаются по одному; перед созданием должны быть выбраны все необходимые параметры запрошенного состава. Предложенный вариант не считается ответом. Значения, уже заданные в запросе, согласованные для текущего применения или однозначно определённые существующим проектом, повторно не спрашиваются.

1. Имя сервиса и расположение нового проекта либо существующего solution.
2. До создания solution с ExportImport (или добавления ExportImport в существующий solution) спроси, какая СУБД нужна. Покажи список для выбора: SQLite, SQL Server (MSSQL), своё значение. Это примеры, а не ограничение допустимых СУБД; другие варианты проверяются по каталогу и документации. Дождись ответа. Для одного Model этот вопрос не нужен.
3. После выбора СУБД отдельным вопросом спроси, какой провайдер использовать, и дождись выбора до создания solution/проектов. Покажи список предлагаемых совместимых провайдеров и возможность своего значения: семейство EF, точное имя пакета, подходящая версия, совместимость с target framework, ограничения и состояние проверки. Например, каталог содержит для SQLite `Microsoft.EntityFrameworkCore.Sqlite` (EF Core), а для SQL Server — `Microsoft.EntityFrameworkCore.SqlServer` (EF Core) и провайдер из `EntityFramework` (EF6). Непроверенный новый профиль обозначай явно. Список зависит от выбранной СУБД и EF и не ограничивается одним default; другие варианты проверяй по актуальной документации разработчика. Выбор провайдера согласуй до создания проекта, не подставляй его молча.
4. Остальные необходимые настройки: семейство/версия EF и target framework в согласованной совместимой комбинации, версии пакетов, логическое имя БД, имя файла без расширения и его расположение для файлового подключения. Если семейство EF уже выбрано вместе с провайдером, повторный вопрос не нужен. Подход текущего процесса — Code First; производные имена проектов, namespaces, solution и контекста показываются по установленным правилам, без независимого переименования.
5. Покажи итоговую сводку и проверь совместимость до создания. Нового общего подтверждения поверх полученных ответов не требуется; нерешённые конфликты уточняются до зависящего от них действия.

Расширение файла определяется выбранной СУБД/профилем, а не добавляется пользователем к базовому имени. Для SQLite в этом workflow используется `.db`; для другой СУБД проверь применимый формат, не придумывай расширение. Серверной СУБД без файла в строке подключения имя файла и расширение не назначаются. Логическое имя БД и базовое имя файла остаются независимыми параметрами.

### Строка подключения SQLite

После выбора имени файла вместо вопроса «Где его размещаем?» задавай вопрос о строке подключения в следующем виде. Подставляй выбранное имя файла с расширением; `book4u.db` здесь только пример.

**Какую строку подключения к SQLite используем?**

1. **Только имя файла:** `ConnectionString = @"Data Source=book4u.db";`

   Путь относительный: файл БД будет находиться в рабочей папке запущенной программы, которая может отличаться от папки проекта.
2. **Полный путь к файлу:** например, `ConnectionString = @"Data Source=D:\Data\book4u.db";`

   Укажи нужный путь.

**Какой вариант выбираем?**

Оставляй возможность свободного ответа. Уже заданную строку подключения или путь повторно не спрашивай. Выбор только имени файла сохраняется как относительный `Data Source`; не заменяй его абсолютным путём к корню проекта и не обещай размещение в корне проекта. При выборе полного пути используй указанный Parad путь. В итоговой сводке показывай фактическую строку подключения. Этот вопрос относится к SQLite; параметры серверной СУБД определяются её профилем.

## Как начать

Основная фраза:

```text
Создай библиотеку контрактов данных для приложения Monitor. Веди меня пошагово.
```

Можно сразу указать известные параметры:

```text
Создай библиотеку контрактов данных для приложения Monitor в <путь к solution> на <target framework>. Веди меня пошагово.
```

Если обязательных сведений не хватает, Машина задаёт только один следующий необходимый вопрос. Не нужно заранее помнить всю последовательность или отвечать на большую анкету.

## Шаг 1. Начальные параметры

Используется раздел «Параметры по умолчанию» выше. В итоговой сводке раздельно показываются сервис, проекты и namespaces, расположение, framework, семейство EF, provider и версии, логическое имя БД, контекст, а для файлового подключения — базовое имя файла, расширение и фактическая строка подключения. Параметры, не относящиеся к запрошенному составу, не добавляются в анкету.

## Шаг 2. Стартовый проект

Машина выполняет [[Commands/Create Project Domain Model by Step]]. Готовый состав образца переносится по правилам команды. Фактическое состояние сохраняется в solution и коде, дополнительные сведения — при необходимости в существующей задаче; отдельного паспорта нет.

### Сборка и команды создания БД

Порядок сборки, подготовки фабрики и отдельных действий с migrations: [[Commands/Create Project Domain Model by Step#Сборка, migrations и создание БД]]. Эта ссылка применяется после создания стартового solution или при явном запросе подготовки migration.

## Шаг 3. Добавление данных

Передай описание новых объектов либо дополнений в чате или доступном файле. Состав и Excel-процесс определяются [[Documents/Architectures/Cubes/DotNet/DomainObject - Entity - MappingEF - Repository#Гибкий состав работы и согласование модели]]; выполнение — [[Commands/Create Data Objects by Step]].

### Описание в чате

```text
Добавь DomainObject Product: ID long, Code string, Name string, Price decimal.
```

Если поля не перечислены, применяется согласованный шаблон `DomainObject` по умолчанию.

`CommandResult` показывает стиль оформления и реализации класса; его предметные поля и перечисления не копируются автоматически в каждый новый DomainObject. Для нового класса используется его собственное описание и общие обязательные правила, включая первое поле `ID long` и `Code`. Предварительный разбор класса согласуется в Excel; после возврата утверждённой книги отдельное подтверждение кода не требуется.

### Описание в файле

```text
Добавь DomainObject из приложенного файла.
```

или:

```text
Разбери приложенный файл и добавь из него все контракты данных.
```

Формат файла может быть любым, если из него можно извлечь описание объектов и полей. Один файл может содержать один объект или список объектов.

## Восстановление состояния

Для продолжения достаточно запроса, фактических solution, .csproj, кода и существующей рабочей задачи. Восстанови утверждённый Excel, состав, готовые файлы и нерешённое; не повторяй завершённую генерацию. Полное восстановление harness описано отдельно и не требуется при обычном продолжении.
