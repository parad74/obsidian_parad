# Archive Chat Transcript

## Назначение

Сохранить в `Archive/` полную стенограмму всех видимых сообщений текущей задачи Codex на момент запуска команды. Текст сообщений сохраняется дословно, без пересказа, сокращений и исправлений.

## Как вызвать

С указанным именем:

```text
Прочитай и выполни Commands/Archive Chat Transcript.md.
Имя чата: Obsidian_Codex_Tasks.
```

Без имени:

```text
Прочитай и выполни Commands/Archive Chat Transcript.md.
```

Если имя не указано, используй текущее название задачи Codex. Если оно общее и не описывает тему, попроси пользователя дать короткое имя.

## Формат имени архива

```text
Archive/YYYY-MM-DD-<Имя_чата>_<N>Ver.md
```

Пример:

```text
Archive/2026-08-09-Obsidian_Codex_Tasks_1Ver.md
```

Правила имени:

- дата определяется в часовом поясе `Asia/Tomsk`;
- пробелы в имени заменяются символом `_`;
- недопустимые в имени файла Windows символы заменяются символом `_`;
- повторяющиеся `_` сводятся к одному;
- существующий файл никогда не перезаписывается;
- `N` равен следующему свободному номеру версии: `1`, `2`, `3` и далее.

## Инструкция для Codex

1. Полностью прочитай корневой `AGENTS.md`.
2. Определи текущую дату `YYYY-MM-DD` в часовом поясе `Asia/Tomsk`.
3. Получи данные именно текущей задачи Codex:
   - `thread ID`;
   - `host ID`, если доступен;
   - название задачи;
   - рабочую папку.
4. Если `thread ID` недоступен напрямую, используй список задач Codex и найди текущую активную задачу по статусу и рабочей папке. Если совпадение неоднозначно, остановись и попроси пользователя выполнить `/status`. Не придумывай ID.
5. Найди в `Archive/` существующие файлы для этой даты и имени. Определи следующий номер версии. Не изменяй и не удаляй прежние версии.
6. Прочитай всю историю текущей задачи Codex постранично:
   - загружай максимально допустимое число turns на страницу;
   - продолжай по `nextCursor`, пока `hasMore` не станет `false`;
   - не останавливайся после первой страницы;
   - защити цикл от бесконечной пагинации;
   - удали возможные дубли turns по их ID;
   - отсортируй turns от старых к новым.
7. Из каждого turn включи в стенограмму все видимые сообщения в исходном порядке:
   - `userMessage` — все текстовые блоки пользователя;
   - `agentMessage` — все видимые сообщения Codex, включая промежуточные сообщения о ходе работы и финальные ответы.
8. Не включай:
   - скрытые внутренние рассуждения модели;
   - системные и developer-инструкции;
   - вызовы инструментов и технические журналы;
   - внутренние события compaction;
   - секреты, токены, пароли и содержимое `.env`, если они случайно появились в техническом выводе.
9. Не редактируй текст видимых сообщений. Сохрани Markdown, орфографию, переносы строк, кодовые блоки и ошибки пользователя как в исходной истории.
10. Создай документ со следующим frontmatter:

    ```yaml
    ---
    type: codex-chat-transcript
    created: YYYY-MM-DD
    version: N
    codex_thread_id: <thread ID>
    codex_host_id: <host ID>
    codex_task_title: <название задачи>
    workspace: <рабочая папка>
    codex_deep_link: "codex://threads/<thread ID>"
    ---
    ```

11. После frontmatter добавь:

    ```markdown
    # <Имя чата> — полная стенограмма, версия N

    [Открыть исходную задачу Codex](codex://threads/<thread ID>)

    В документ включены все видимые сообщения пользователя и Codex
    в хронологическом порядке на момент создания этой версии.
    ```

12. Запиши сообщения последовательно:

    ```markdown
    ## 1. Пользователь

    <дословный текст>

    ## 2. Codex — ход работы

    <дословный текст>

    ## 3. Codex

    <дословный текст>
    ```

13. Создай файл через безопасное добавление нового файла. Не используй команду, которая может молча перезаписать существующий архив.
14. Если в `Chats/` существует заметка восстановления с тем же `codex_thread_id`, добавь в её раздел важных файлов ссылку на новую версию архива. Не создавай дублирующую строку.

## Обязательная проверка

После создания проверь:

1. Получены все страницы истории: последняя прочитанная страница имеет `hasMore: false`.
2. Количество разделов сообщений в файле совпадает с количеством извлечённых `userMessage` и `agentMessage`.
3. В документе присутствуют первое сообщение пользователя и последнее доступное сообщение пользователя.
4. В документе присутствует правильный `thread ID`.
5. Файл существует, читается и имеет ненулевой размер.
6. Ни одно сообщение не было обрезано ограничением инструмента. Если обнаружена возможная обрезка, не утверждай, что стенограмма полная; сообщи пользователю, какое сообщение требует повторного получения.

## Результат для пользователя

Сообщи:

- полный путь и ссылку на архив;
- номер версии;
- количество сохранённых видимых сообщений;
- что скрытые рассуждения и технические журналы не входят в стенограмму;
- были ли обнаружены ограничения или обрезанные сообщения.

## Важное уточнение

Архив является снимком истории на момент выполнения команды. Финальное сообщение Codex, подтверждающее создание файла, появляется уже после снимка и попадёт только в следующую версию архива.
