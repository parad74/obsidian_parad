# Create Project Domain Model by Step — v2

## Назначение

Команда создания, продолжения и наполнения `<Service>.Model`, стартового ExportImport solution и определения следующего шага. Перед работой прочитай [[Documents/Architectures/Data Model Harness]] и выбранные карточки. Вопросы находятся в пользовательской инструкции, контракты — в архитектурных карточках, код — в фиксированных примерах. Документ обсуждения не используется.

## Результат

Создать запрошенный состав по согласованным параметрам и показать проверенный результат. Роли и допустимые зависимости определяются [[Documents/Architectures/Data Model Harness#Модули и устойчивые границы]]. Имена определяются [[Wiki/HowToDo/Create Project Domain Model by Step#Параметры по умолчанию]].

## Состав solution

Для запроса создать `<Service>.Model` базовый состав — Model и SelectParam. Для запроса создать `<Service>.Model.Sqlite.CodeFirst.ExportImport` базовый состав — три проекта: ExportImport, Model и SelectParam. Новый автономный solution называй именем сервиса, выбранным в начале: `<Service>.sln`. Имя БД и имя ExportImport-проекта это имя не меняют. Если необходимого проекта нет, создай или подключи его в рамках запрошенной работы. Эти составы не задают общий запрет включать другие проекты в solution; ограничения `ProjectReference` конкретной библиотеки описывают её зависимости, а не членство проектов в solution.

Способ переноса SelectParam: [[Documents/Architectures/LibProject/netstandard2.0/SelectParam#Перенос в рабочее приложение]].

Запрос создать `<Service>.Model.<DataStore>.CodeFirst.ExportImport` означает создание готового стартового solution по образцу, а не пустой инфраструктурной оболочки. В `<Service>.Model` включаются готовые `CommandResult`/`CommandResults`, необходимые перечисления и пять интерфейсов. В ExportImport для `CommandResult` создаются или адаптируются `Entity`, Fluent-конфигурация, `DbSet` в `<ИмяБД>Context`, MappingEF и EF-репозиторий; интерфейс репозитория находится в Model. Этот стартовый комплект переносится без повторного согласования состава `CommandResult`. Гибкий выбор этапов кубика применяется к последующему созданию и дополнению других объектов и не сокращает стартовый комплект нового ExportImport solution. Проверка результата выполняется по разделу «Сборка, migrations и создание БД».

В стартовый Model также входит NoEntityAttribute. Готовый состав переносится по [[Documents/Architectures/Data Model Examples#Применение готового состава]]; для него не требуется Excel нового предметного описания. Другие предметные объекты и тестовые данные по умолчанию не добавляются. Неиспользуемые части стартового комплекта сохраняются по [[Documents/Architectures/LibProject/netstandard2.0/Monitor.Model#Образец как опора при создании модели]].

## Сборка, migrations и создание БД

После создания стартового solution собери его. Если сборка успешна, сообщи Parad, что solution собирается, с фактическим результатом сборки. Если сборка не прошла, не переходи к migrations и БД до устранения относящихся к созданному решению ошибок. Отдельные тестовые проекты и автоматизированные тесты на текущем этапе не создавай.

После успешной сборки проверь готовность выбранного EF-профиля к design-time-командам: наличие совместимого инструмента, необходимых design-time packages и способа создать `<ИмяБД>Context`. При создании solution с ExportImport необходимая design-time фабрика контекста входит в подготовку к миграциям и добавляется без отдельного согласования. Используй уже выбранные провайдер и строку подключения. Если существующий способ создания контекста работает, вторую фабрику не создавай. После добавления фабрики проверь сборку и создание контекста design-time-командой без создания или изменения БД. Фабрика не вызывает DbInitializer, Migrate или EnsureCreated. Для отсутствующих packages сохраняется отдельное согласование, если их добавление ещё не разрешено Parad; это уточнение отменяет дополнительный вопрос о фабрике, а не меняет правила зависимостей. Создание и применение самих migrations остаются отдельными действиями по запросу Parad.

Когда профиль готов, выдай Parad две точные команды с фактическими путями, проектом, startup project и контекстом: сначала создание migration `InitialCreate`, затем применение migrations для создания отсутствующей БД. Для EF Core это соответственно `dotnet ef migrations add InitialCreate ...` и `dotnet ef database update ...`; для EF6 — команды выбранного поддерживаемого инструмента `Add-Migration InitialCreate` и `Update-Database`. Покажи рабочую папку и полный набор параметров, а не только сокращённые имена команд.

По умолчанию только покажи команды. Машина может выполнить каждое действие сама по отдельному явному запросу Parad. Создание migration изменяет исходники, а применение migration создаёт или изменяет БД, поэтому это два раздельных действия. Перед применением проверь целевое подключение и наличие БД; существующую БД без отдельного явного разрешения не обновляй. После создания `InitialCreate` и отсутствующей БД проверь, что БД создана, migration применена и ожидаемая схема присутствует, затем сообщи результат Parad.

## Стиль интерактивной работы

Назови текущий этап, известные параметры и следующий необходимый вопрос или действие. Вопросы создания задаются по [[Wiki/HowToDo/Create Project Domain Model by Step#Порядок вопросов перед созданием]]. Не превращай предложение Машины в правило до решения Parad. Выполненное и нерешённое при необходимости сохраняются в существующей рабочей задаче; отдельный паспорт и обязательный формат не создаются.

## Последовательность

1. Восстанови запрос, фактические solution/проекты, .csproj, исходники и существующую рабочую задачу. При продолжении используй уже созданное; история обсуждения не является зависимостью работы.
2. Перед созданием проекта выполни [[Wiki/HowToDo/Create Project Domain Model by Step#Параметры по умолчанию]] и проверку совместимости. При исследовании нового provider используй правила каталога.
3. Создай либо подключи запрошенный стартовый состав по разделу «Состав solution», используя [[Documents/Architectures/Data Model Examples]]. Приведи namespaces, ссылки на типы и соответствующие сервису имена; не добавляй другие демонстрационные модели и данные.
4. Для новых предметных объектов или их дополнения используй [[Commands/Create Data Objects by Step]]. Контракт DomainObject: [[Documents/Architectures/LibProject/netstandard2.0/Monitor.Model#Контракт новых DomainObject]]. Факт включения Model в solution не означает запрос создать все предметные модели.
5. Для отдельно выбранных готовых HTTP request/response-контрактов или функциональных наборов используй [[Documents/Architectures/Data Model Examples#Тип 2 — пары request/response]] и [[Documents/Architectures/Data Model Examples#Тип 3 — наборы для стандартной функциональности]]. Покажи фактические исходники и по просьбе пример использования в старом коде; дополнительные связанные типы выбираются по правилам каталога примеров.
6. Проверь сборку, локальные ProjectReference, namespaces, состав и контракты, отсутствие несогласованной инфраструктуры в Model. Итоговый показ и маркировка: [[Documents/Architectures/Cubes/DotNet/DomainObject - Entity - MappingEF - Repository#Показ кода и отметки вычитки]]. Назови один следующий архитектурный этап; состав solution не ограничен навсегда стартовыми проектами.
