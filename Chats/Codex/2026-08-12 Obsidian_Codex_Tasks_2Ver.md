## Контекст и цель

Parad и Машина настраивают минимальную и понятную систему ведения задач в Obsidian для общей работы и .NET-проектов. Каждая задача хранится отдельной карточкой в `Tasks/Items/<Project ID>/`, а корневые документы содержат только динамические представления Obsidian Tasks.

Сегодня основная работа была посвящена разделению задач по фактическому состоянию, хранению завершённых, приостановленных и отменённых карточек, а также динамической группировке списков по проектам.

## Что уже сделано

- `Inbox.md` переименован в `InProcess.md`.
- Создан `Tasks/ToDo.md` для неначатых задач со статусами `Todo` и `Important` (`TODO`).
- `Tasks/InProcess.md` показывает только начатую работу и проверку: `Doing`, `InProgress`, `Review`, `Checked` (`IN_PROGRESS`).
- Создан `Tasks/Today.md` с блоками текущей работы, задач на сегодня и завершённых сегодня.
- Создан `Tasks/OnHold.md` для `Waiting`, `Blocked`, `Scheduling`, `Question` (`ON_HOLD`).
- Создан `Tasks/Cancelled.md` для отменённых задач (`CANCELLED`).
- Завершённые карточки перемещаются в `<Project ID>/done/`.
- Приостановленные карточки перемещаются в `<Project ID>/on_hold/`.
- Отменённые карточки должны перемещаться в `<Project ID>/cancelled/` и сохраняться для истории.
- При повторном открытии карточка возвращается в активную папку проекта и получает фактический рабочий статус.
- Во всех карточках над единственной строкой задачи используется заголовок `## Проект: <Project ID>`.
- Корневые списки используют `group by heading`, поэтому проект появляется только при наличии подходящих задач и пустые заголовки не показываются.
- Служебные папки `done/`, `on_hold/` и `cancelled/` не становятся отдельными проектами.
- Правила закреплены в `AGENTS.md`.
- Изменения сохранены в private-репозитории `parad74/obsidian_parad`, ветка `main`, коммит `539389df18a6ee489d2851575ecb098777e48a93`.

## Принятые решения

### Смысл корневых списков

| Документ | Что показывает |
| --- | --- |
| `ToDo.md` | Работу ещё не начинали: `Todo`, `Important` |
| `InProcess.md` | Работа началась или проверяется: `Doing`, `InProgress`, `Review`, `Checked` |
| `Today.md` | Текущая работа, задачи с датой на сегодня, завершённые сегодня |
| `OnHold.md` | Работа принудительно приостановлена |
| `Cancelled.md` | Задачи решено не выполнять, но история сохранена |

### Проекты

- Каждая карточка относится либо к `General`, либо к одному стабильному `Project ID`.
- `General` используется только для vault, обучения, личной организации и действительно общих задач.
- Рабочие списки едины для всего vault и внутри динамически группируются по проектам.
- Если в конкретном списке нет задач проекта, заголовок проекта не отображается.
- Отдельные корневые документы для каждого проекта пока не создаются.

### Жизненный цикл файлов

- Активная карточка: `Tasks/Items/<Project ID>/`.
- Завершённая: `Tasks/Items/<Project ID>/done/`.
- Приостановленная: `Tasks/Items/<Project ID>/on_hold/`.
- Отменённая: `Tasks/Items/<Project ID>/cancelled/`.
- Перемещение файла не изменяет `project` во frontmatter и заголовок `## Проект: ...`.

## Рекомендации на будущее

### Следующий полезный список

Создать единый `Tasks/Done.md` для всех успешно завершённых задач. Желаемый вид:

```text
Проект: General
  2026-08 Август
    завершённые задачи

Проект: dotnet_architecture_examples
  2026-08 Август
    завершённые задачи
```

Проект и месяц должны появляться только при наличии задач. Месячный раздел может формироваться автоматически сразу после первой завершённой задачи месяца; отдельный процесс в последний день месяца не нужен.

Для автоматической группировки даты `✅` по месяцам Obsidian Tasks требуется `group by function`, а значит локальное разрешение `Settings → Tasks → Searches → Enable custom searches`. Оно включается отдельно на каждом устройстве. Сегодня эта настройка не была включена, а `Done.md` не был создан.

### Значение дат

Позже полезно окончательно закрепить:

- `Due` — крайний срок;
- `Scheduled` — день, когда планируется выполнять задачу;
- `Start` — дата, раньше которой работу не начинать.

Не добавлять даты без явного основания в словах пользователя или исходном документе.

### Регулярный разбор

- Периодически просматривать `OnHold.md`, например раз в неделю.
- Для каждой карточки принимать одно решение: оставить на паузе, вернуть в работу, завершить или отменить.
- Позже определить, нужен ли отдельный ежемесячный обзор `Cancelled`; сейчас достаточно единого динамического списка.

### Что пока не усложнять

- Не добавлять подзадачи и зависимости без реальной необходимости.
- Не вводить дополнительные уровни приоритета сверх `Important`.
- Не создавать отдельные дашборды и файлы списков для каждого проекта.
- Не строить сложную иерархию категорий внутри проектных папок.
- Не добавлять автоматические напоминания, пока не сформирован устойчивый ежедневный процесс.
