## Контракт первого прохода

Сохраняется и при повторной генерации; расширенный текущий состав находится в README.

Это реализованный контракт HTTP-слоя для вычитки, а не новое общее правило модели:

| Операция | Основание и ожидаемое поведение |
| --- | --- |
| Получить по Code | Один DomainObject; отсутствие записи выражается HTTP-ответом 404. |
| Получить выборку | SelectParams применяется репозиторием; ответ содержит items и totalCount. Дополнительные свойства ObservableCollection напрямую не сериализуются как метаданные массива. |
| Вставить объект | Синхронный Insert возвращает ID, выданный БД. Входной ID не объявляется ID новой записи. |
| Обновить по ID / по Code | Вызывать соответствующий метод репозитория и дождаться Task; ID и поисковый Code не смешиваются. Не возвращать входной ID как доказательство фактически изменённой строки. |
| Удалить по Code | Дождаться DeleteByCode, который удаляет все совпадения. Не переносить смысл старого DeleteByCommandResultCode. |

Существующий контракт изменения возвращает Task без признака наличия записи и числа изменений. Поэтому он сам по себе не позволяет обещать HTTP 404 или количество изменённых строк. Поэтому PUT/DELETE возвращают 204 после завершения операции, включая отсутствие совпадений; ошибки операции возвращают 500. Сигнатуры существующих репозиториев не менялись. Новые поля предметной модели для этого не требуются.

Первый конкретный потребитель подтвердил вопрос об относительном пути: существующая БД находится в папке ExportImport, а запуск нового host из своей папки может выбрать другой book4u.db при той же строке. Дополнительный опыт первого применения:

- Старый SelectParam вставляет строки в выражение без экранирования, а [All] имеет особый смысл в одном виде фильтра. HTTP-адаптер использует проверенные имена сортировки, удвоение кавычек по фактическому парсеру и строковый списочный фильтр из одного значения. Проверки подтвердили точное сравнение специальных значений; SelectParam глобально не переписывался.
- Host.CreateDefaultBuilder на Windows добавлял EventLog. Искусственная ошибка БД обнаружила, что ошибка записи в этот журнал разрушает HTTP-обработку; явный состав Console/Debug устранил зависимость. Это настройка данного локального host, а не универсальный запрет EventLog.
- При неподходящей конфигурации первоначальный необработанный выход .NET 3.1 задерживался. Main явно сообщает причину и возвращает 1; в первом проходе проверялись отсутствие БД и недопустимое значение настройки. После вычитки отсутствие файла стало сценарием инициализации; отказ проверяется для ошибки создания и неправильных настроек.
- Предметные объекты не создавались и не расширялись. Три новых типа в Contracts описывают только HTTP-вход/выход; Excel-процесс предметной модели в этом составе не запускался. При дальнейшем уточнении маршрутизации полезно сохранить явную границу между контрактом транспорта и DomainObject.
