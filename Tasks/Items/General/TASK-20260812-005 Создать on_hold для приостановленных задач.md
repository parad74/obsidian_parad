# TASK-20260812-005 — Создать on_hold для приостановленных задач

## Проект: General

- [r] Создать on_hold для приостановленных задач 🆔 TASK-20260812-005

## Цель

Отделить принудительно приостановленные задачи от текущего рабочего процесса, сохранив единое место для их периодического анализа, окончательного закрытия или возврата в работу.

## Описание

Добавить подпапки `on_hold/` внутри проектных контекстов, страницу `Tasks/OnHold.md` и правила автоматического перемещения карточек со статусом типа `ON_HOLD`.

## Критерии приёмки

| ID | Критерий |
| --- | --- |
| AC-1 | Статусы `Waiting`, `Blocked`, `Scheduling` и `Question` перемещают карточку в `<Project ID>/on_hold/` |
| AC-2 | Задачи типа `ON_HOLD` не отображаются в основном `InProcess` и блоках текущей работы Today |
| AC-3 | Страница `Tasks/OnHold.md` показывает все приостановленные задачи и группирует их по проекту и статусу |
| AC-4 | При возврате к работе карточка переносится из `on_hold/` в корень папки проекта |
| AC-5 | При завершении карточка переносится из `on_hold/` в `done/` и получает дату завершения |
| AC-6 | Навигация между корневыми списками задач доступна с каждой страницы |
| AC-7 | Периодический анализ предполагает одно из решений: оставить на паузе, вернуть в работу, завершить или отменить |

## Ограничения

- Не добавлять новые статусы Obsidian Tasks.
- Не использовать JavaScript-фильтры.
- Не смешивать задачи разных проектов в одной файловой папке.
- Не считать `Checked` или `Cancelled` статусами `on_hold`.
